## Invariants

### Technical
  - I1: `devkit init` on an already-initialized directory is a no-op. It never overwrites existing files or directories — only creates missing ones and reports skipped.
  - I2: RFC, INV, and ESC identifiers are assigned by incrementing the highest existing numeric suffix. Deleting a file does not reclaim its number. IDs never collide under single-process usage.
  - I3: The system enforces a fixed five-phase pipeline: research -> product -> arch -> spec -> qa. Advance moves exactly one step. There is no skip and no retreat command.
  - I4: Phase advancement is blocked if ANY gate condition is unsatisfied. Empty conditions array also blocks (safe-fail default via `length > 0 && every()`).
  - I5: File modification detection uses truncated SHA-256 content hashes (12 hex chars), not filesystem timestamps. Identical content at different times = no diff. Changed content at same second = detected.
  - I6: An invariant is "covered" when mentioned in >=2 distinct sources (test files + contract docs). 1 source = partial. 0 = uncovered. Partial does NOT count toward coverage percentage.
  - I7: `resolveRfc` and `resolveInvestigation` rewrite artifact files via line-prefix replacement with direct `writeFileSync`. No backup, no atomic rename, no intermediate file.
  - I8: `detectProjectState` returns one of four mutually exclusive states in strict priority: initialized > upgrade > brownfield > greenfield. Same filesystem state always produces same result.
